# 카페 인기탭 발굴기 — sub3 완전 세팅 & 방법론 (cafe_kw_probe.py)

**플레이스 주소 하나 넣으면 → 그 업체가 진입 가능한 "인기탭(인기글 섹션) 키워드"를 넓은→좁은으로 발굴**하는 CLI.
git pull 하고 아래 명령만 치면 바로 된다. (읽기 스캔 전용, 대량 발행 아님)

---

## 0. 30초 요약 (바로 쓰기)
```bash
git pull
pip install truststore requests beautifulsoup4 python-dotenv
cd crawler
python cafe_kw_probe.py <플레이스URL 또는 placeId> --place --ad --target 5
```
→ 검색량순으로 "진입 가능한 인기탭 키워드" 5건을 찾으면 자동 중단. Supabase 키 불필요.

---

## 1. 무엇을 / 왜
- **무엇**: 네이버 플레이스 업체 → 그 지역·업종의 **인기글 섹션(인기탭)에 카페로 들어갈 수 있는 키워드** 목록.
- **왜 sub3에서도**: 인기탭 판정은 `m.search`를 **우리 IP로 스크랩**한다. 한 IP로 몰면 네이버가 일시차단(429/403). → **main / sub3 두 IP로 분산**하면 차단 위험↓. (우리 자체 PC라 프록시 금지 정책과 무관)
- **sub3 역할**: 두 번째 스캔 IP = 부하 분산 + main 차단 시 폴백.

## 2. 작동 원리 (2단계)
```
[1단계] 검색량 API (차단 0)               [2단계] 인기탭 판정 (우리 IP 스크랩)
플레이스 주소                              1단계에서 뽑은 키워드를
 → 업체명·업종·주소(플레이스 조회)     →     m.search로 긁어 "인기글 섹션 있나 / 누가 있나" 확인
 → 검색광고 keywordstool 로 연관키워드+검색량        → 카페분산(진입기회) 인 것만 결과
```
- 1단계(검색광고 API)는 **CF 서버 경유 공식 API → 차단 없음**.
- 2단계(m.search)만 우리 IP = 차단 위험. 그래서 **`--target`로 필요한 만큼만** 긁는다.

## 3. 넓은→좁은 계층 (핵심 방법론)
가장 큰 키워드에서 점점 좁혀간다. **지역 계층 × 업종 계층**을 조합:

**지역 계층 (주소에서 자동 추출, 넓은→좁은)**
```
도(경기도/전북) → 시(수원/군산) → 구(장안구) → 동(연무동/선유도동) → 상권(광덕/창훈)
```
**업종 계층 (업종·플레이스키워드에서, 넓은→좁은)**
```
맛집 → 업종맛집(생선회 맛집) → 회 맛집 → 횟집 → 업종(생선회) → 요리맛집(광어맛집·물회맛집) → 요리(광어·물회)
※ 음식점만 '맛집' 계층. 비음식(인테리어 등)은 업종→축약코어(인테리어디자인→인테리어)→세부니치.
```
**조합 예 (광교횟집=수원 장안구 / 생선회)**
```
경기도 맛집 → 수원 맛집 → 장안구 맛집 → 연무동 맛집
→ 수원 회 맛집 → 수원 횟집 → 수원 매운탕 → 수원 물회 → 수원 우럭 …
```
여기에 **검색광고 검색량 니치**(거실인테리어·물회맛집·조개구이무한리필 등)까지 합쳐 후보를 만든다.

## 5. 사용법
```bash
cd crawler
python cafe_kw_probe.py <플레이스URL/placeId> --place --ad --target 5   # 권장: 5건 찾으면 중단
python cafe_kw_probe.py "https://naver.me/xxxx" --place --ad --target 5
python cafe_kw_probe.py 1066951825 --place --ad --target 10
python cafe_kw_probe.py --self-test                                     # QA(스크랩 5회)
```
### 플래그
| 플래그 | 뜻 | 권장 |
|---|---|---|
| `--place` | 플레이스 주소/ID 입력 | 항상 |
| `--ad` | 검색광고 검색량 소싱(차단0) | **항상 켬** |
| `--target N` | **N건 찾으면 중단**(스크랩 최소화) | **항상**, N=하루 접수 건수 |
| `--deep` | 인기탭 승자 재귀 확장(세부까지·스크랩↑) | 급할 때만 |
| `--max N` | 최대 스캔 수 | target 쓰면 불필요 |
| `--fresh` | 캐시 무시 강제 재스캔 | 쓰지 말 것 |

## 6. ⚠️ 차단 회피 규칙 (반드시)
1. **`--target`로 소량만.** `--deep`/`--max 200` 같은 대량 스캔 금지 (main이 그래서 429 맞음)
2. **캐시 존중** — `cafe_kw_cache.json`(로컬·7일). 이미 본 건 재스캔 안 함. 지우지 말 것
3. **403/429("과도한 접근") 뜨면 즉시 중단** → **1시간 이상 쉬고** 재개. 계속 찌르면 차단창 갱신돼 더 길어짐
4. 코드 내장 간격(`_pause` 1.2초+지터) 빼지 말 것
5. main과 **같은 업체 동시 스캔 금지** — 업체/요청 나눠 맡기

## 7. 결과 읽기
```
✅[3/5] [수원 횟집] 「맛집 인기글」 | 3위:foodeats     ← 인기탭 있음 + 진입 여지(1·2위 공석)
· [수원 생선회] 섹션없음                              ← 인기탭 없음(카페로 못 먹음)
→ 5건 발견 (라이브 스크랩 18건, 상한 40)              ← 실제 스크랩 18건만
=== 요약 ===  🎯 발견 5/5건: 수원 맛집, 수원 횟집, ...
```
- `카페분산(기회)` = 카페 자리가 독점 안 됨 → 진입 가능. `1위 빔` 이면 특히 좋음
- 표의 `2위:카페명` = 지금 그 자리를 차지한 **다른 카페**(우리가 이미 뜬 게 아님)
