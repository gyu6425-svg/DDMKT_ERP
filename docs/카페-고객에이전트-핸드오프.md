# 카페 발행 — 불특정 고객 배포 에이전트 (세션 핸드오프)

**목표:** 불특정 고객이 **직접** 자기 카페에 자동발행. 웹 UI(호스팅) + 그 PC의 로컬 에이전트.
결정: MCP 아님(고객 셀프서비스엔 웹UI+에이전트가 정답). 카페별 로그인된 크롬이 어떤 PC엔 물리적으로 필요.

## 아키텍처 (독립검증 확정)
- **발행 = Playwright가 시스템 크롬에 CDP attach**(`publish_cafe.py` `connect_over_cdp`). 크로미움 번들 불필요 → exe 수십MB.
- python 서드파티 **딱 4개**: playwright·requests·truststore·pillow.
- **AI 생성 = 이미 Cloudflare 함수**(`functions/api/generate-*`) — 키 서버보관. 단 로컬 orchestrator가 아직 OpenAI 직접호출(`cafe_auto_publish*.py`) → CF 경유로 바꿔야 로컬 키 0.
- **서비스키 클라 불필요**: 브라우저가 이미 publishable키+내부인증으로 큐insert/upload/select/download 함(`src/api/cafePublishQueue.ts`). RLS = `for all to authenticated is_internal()`(`docs/cafe-publish-queue.sql`). → 에이전트도 서비스키 대신 publishable+내부계정 로그인으로 전환 가능.

### 2. 서비스키 → publishable+내부JWT ✅ (코드 완료)

- `publish_cafe.py`(`_headers`→sb_auth, `auth_ready()` 추가), `publish_listener.py`(가드 `pc.auth_ready()`), `cafe_auto_publish_nusu2.py`/`_ddclean.py`(`sb_headers`→sb_auth, main 가드) 전환.
- 전제: 내부 전용 Supabase 계정이 `is_internal()`=true (profiles.is_active=true, client_id NULL — `docs/enable-login-rls.sql`).
