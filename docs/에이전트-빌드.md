# 카페 고객 에이전트 — 빌드·패키징 (Phase 3)

고객 PC용 단일 실행본(exe) + 설치 마법사를 만든다. 라이브 발행 코드와 무관(순수 패키징).

## 고객 배포(경량) — 고객은 편집·명령어 없이 더블클릭만
`build_agent.ps1` 이 만드는 `DDMKT-Agent.zip` 에는 exe·런타임 + 도우미 3종이 들어간다:
- **`1-로그인.bat`** — 크롬을 띄워 네이버 로그인(최초 1회). 폴더 기준 `chrome_profile` 에 세션 저장.
- **`2-시작.bat`** — `DDMKT-Agent.exe` 실행(발행 시작).
- **`사용법.txt`** — 고객 안내(2단계).

담당자(우리)가 할 일: 압축 풀어 **고객별 `agent.env`** 채워 넣고(카페 URL·게시판 + 내부계정, publishable·CF 는 공통) 다시 압축해 전달.
고객이 할 일: 압축 풀기 → `1-로그인.bat` → 로그인 → `2-시작.bat`. 끝. (크롬만 설치돼 있으면 됨. 미서명이라 첫 실행 "추가 정보 → 실행".)
⚠️ `agent.env`(실비번)는 zip·git 에 커밋하지 않는다(`.gitignore`).

## 원칙 (지키지 않으면 깨짐)
- **PyInstaller `--onedir`** 만. ❌ `--onefile` 금지 — temp 압축해제로 `__file__`/데이터 경로 가정이 깨지고 백신 오탐.
- **`playwright install` 절대 금지** — 크로미움 번들 불필요(시스템 크롬에 CDP attach). 브라우저 다운로드 0.
- 서드파티 4개만: `playwright · requests · truststore · pillow`.
- **UPX 압축 금지**(백신 오탐).
- `agent.env`·`chrome_profile`·`assets`·`logs` 는 **exe 옆 데이터 폴더**(런타임). exe 에 번들 금지 — 업체마다 다름.
  - 프리즈 시 `agent_main` 이 `CAFE_DATA_DIR`(=exe 폴더)를 env 로 넘겨, 하위 모듈이 그 폴더에서 설정·프로필을 찾는다. (개발/라이브에선 env 미설정 → 기존 `__file__` 경로, 동작 무변경.)

## 1) 빌드
```powershell
cd crawler\cafe_pub
powershell -ExecutionPolicy Bypass -File build_agent.ps1
```
- 의존성(+PyInstaller) 설치 → `agent.spec` 로 빌드.
- 산출: `dist\DDMKT-Agent\DDMKT-Agent.exe` (+ `_internal\`).

### 스모크 테스트(빌드 직후)
```powershell
cd dist\DDMKT-Agent
copy ..\..\agent.env.example agent.env   # 값 채우기(CAFE_WRITE_URL·publishable·CAFE_GENERATE_API 등)
.\DDMKT-Agent.exe
```
- `[agent] 브릿지 스레드 기동` + `listener 시작` 로그가 뜨면 정상.
- ⚠️ 최초 1회 네이버 로그인은 보이는 크롬으로(온보딩 UI '로그인 창 열기' 또는 수동 `--remote-debugging-port`). 세션은 `chrome_profile\` 에 저장 → 이후 헤드리스 attach.

## 2) 코드서명 (Authenticode) — 유료 고객 필수
서명 안 하면 SmartScreen '알 수 없는 게시자' 경고. EV/OV 코드서명 인증서로:
```powershell
signtool sign /fd sha256 /tr http://timestamp.digicert.com /td sha256 /a `
  dist\DDMKT-Agent\DDMKT-Agent.exe
```
- 설치본(setup.exe)도 서명한다. `installer.iss` 의 `SignTool=` 주석을 해제하면 Inno 가 컴파일 시 자동 서명.

## 3) 설치 마법사 (Inno Setup)
```powershell
"C:\Program Files (x86)\Inno Setup 6\ISCC.exe" installer.iss
```
- 산출: `Output\DDMKT-Agent-Setup-1.0.0.exe`.
- 설치 위치 `%LOCALAPPDATA%\DDMKT-Agent`(관리자 권한 불필요), 데이터 폴더 생성, 바탕화면 바로가기, `agent.env` 없으면 견본으로 생성(업그레이드 시 고객 값 보존), 설치 후 `agent.env` 열기.
- Korean.isl 없다는 오류면 Inno Setup 재설치 시 한국어 포함 또는 `compiler:Default.isl` 로 임시 대체.

## 4) 업데이트
- **코드**: 새 `dist\DDMKT-Agent\` 로 폴더 교체, 또는 서명된 새 setup 재실행(`agent.env`·`chrome_profile` 보존).
- **자산/설정**: 런치 시 재싱크(아래).

## 남은 설계 — 업체 자산 고객별 다운로드
- 실사·배너 등은 업체마다 달라 exe 에 번들 금지. Supabase storage 에서 **런치 시 다운로드**해 `assets\` 채우고 `CAFE_ASSETS_DIR` 로 가리킨다.
- 플럼빙(`publish_cafe.storage_download`, 내부JWT)은 이미 있음. 필요한 건 **"이 고객이 받을 자산 목록(매니페스트)"** 정의 — 예: storage `agent-assets/<company>/manifest.json` + 파일들. `agent_main` 시작 시 그 목록을 받아 `assets\` 로 내려받는 스텝 추가.
- 발행 자체는 웹UI에서 큐에 넣고 에이전트가 발행만 하는 흐름이면 로컬 자산 불필요(원고·이미지 다 큐 매니페스트에 실림). 로컬 생성(nusu2/ddclean)까지 고객이 쓸 때만 자산 다운로드 필요.
