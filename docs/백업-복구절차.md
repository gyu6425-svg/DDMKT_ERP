## 1. 복호화 — Git Bash 에서

> ⚠ **PowerShell·cmd 에서는 `gpg` 가 실행되지 않습니다.** PATH 에 없습니다.
> 반드시 **Git Bash**(시작 메뉴 → Git Bash)를 여세요.

```bash
cd /c/Users/ddmkt/DDMKT_ERP/_backup/selfhost/2026-08-20

gpg --decrypt --output ddmkt.dump ddmkt-2026-08-20.dump.gpg
# 암호 입력

echo $?      # ← 반드시 0 인지 확인
```

**`echo $?` 를 꼭 하세요.** 복호화가 실패해도 출력 파일은 생깁니다(내용은 쓰레기).
0 이 아니면 그 파일을 쓰면 안 됩니다.

### 내용이 맞는지 확인(선택)

`SHA256` 파일의 `(평문)` 줄과 맞춰봅니다.

```bash
sha256sum ddmkt.dump
grep "(평문)" SHA256
```

> 왜 평문 해시로 보나: gpg 는 잠글 때마다 난수를 섞어서, **같은 데이터라도 다시 잠그면
> 암호문 해시가 달라집니다.** main 과 VM 의 `.gpg` 해시가 다른 건 정상입니다.
> 내용이 같은지는 평문 해시로만 확인할 수 있습니다.

## 2. 복원 — 전체 경로로

> ⚠ `pg_restore` 도 PATH 에 없습니다. 전체 경로를 씁니다.

```bash
PGR="/c/Program Files/PostgreSQL/17/bin/pg_restore.exe"

"$PGR" -l ddmkt.dump | head        # 목차가 읽히는지(1000줄 이상이면 정상)
```

### 🔴 라이브 DB 에 바로 붓지 마세요

```bash
# 이렇게 하면 지금 돌아가는 DB 를 덮어씁니다 — 하지 마세요
"$PGR" -d postgres ddmkt.dump          # ❌
```

**반드시 임시 DB 에 먼저 복원해 내용을 확인**하고, 그다음에 옮기세요.

```bash
PSQL="/c/Program Files/PostgreSQL/17/bin/psql.exe"
"$PSQL" -U postgres -h localhost -c "create database 복구확인"
"$PGR" -U postgres -h localhost -d 복구확인 --no-owner --no-acl ddmkt.dump

# 들어있는지 확인
"$PSQL" -U postgres -h localhost -d 복구확인 -c "select count(*) from public.clients"
```

복원 중 `log_min_messages` / `vault.secrets` 권한 오류 2건은 **정상입니다**(superuser 전용 항목).
데이터에는 영향이 없습니다.

## 3. VM 에서 복구하는 경우

```bash
ssh -i C:\Users\ddmkt\.ssh\ddmkt_vm ddmkt@192.168.0.179

cd ~/backups/2026-08-20
gpg --batch --decrypt --passphrase-file ~/.backup-pass -o /tmp/r.dump ddmkt-2026-08-20.dump.gpg
echo $?

docker cp /tmp/r.dump supabase-db:/tmp/r.dump
docker exec supabase-db psql -U postgres -c "create database 복구확인"
docker exec supabase-db pg_restore -U postgres -d 복구확인 --no-owner --no-privileges /tmp/r.dump
```

## 함정 (QA 실측)

| 증상 | 실제 원인 |
|---|---|
| `gpg: not recognized` | PowerShell 에서 실행함 → **Git Bash** 를 쓸 것 |
| `pg_restore: not recognized` | PATH 에 없음 → 전체 경로 사용 |
| `sha256sum -c SHA256` 이 FAILED | `(평문)` 줄까지 대조해서 그렇습니다. `grep -v "(평문)" SHA256 \| sha256sum -c` 로 거르세요 |
| main 과 VM 의 `.gpg` 크기·해시가 다름 | **정상**입니다(난수 솔트). 평문 해시로 비교하세요 |
| 복호화 실패했는데 파일이 생김 | gpg 는 실패해도 부분 출력을 남깁니다 → `echo $?` 필수 |

## 무엇이 자동으로 확인되고 있나

매일 03:30 백업이 **자기 자신을 검증**합니다(`crawler/selfhost_backup.py`).

1. sha256 — VM 과 main 의 암호문이 같은가(전송 중 깨짐)
2. **복호화** — 암호가 실제로 풀리는가
3. `pg_restore -l` — 목차가 읽히는가
4. **임시 DB 에 데이터까지 전체 복원** → 테이블·RLS·auth.users·비번해시·주요 행수 대조

하나라도 실패하면 종료코드 1 로 끝나고, 감시(`selfhost_guard`)가 백업이 36시간 넘게
갱신되지 않으면 알립니다. **"백업이 있다"가 아니라 "열리고 되살아난다"를 매일 확인합니다.**
