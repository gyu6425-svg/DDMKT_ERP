# 노션 공개 안내 페이지 — 카페 배포 접수 · 충전 요청

2026-08-21. 티에스애드의 공개 노션 페이지(`N사 플레이스`)와 같은 형식으로,
**카페 발행 접수 + 토큰(발행 건수) 요청** 안내 페이지를 만든다.

- 원천: [docs/notion/카페배포-고객안내.md](notion/카페배포-고객안내.md) — **이 파일 하나**
- 발행: [crawler/notion_publish.py](../crawler/notion_publish.py) — 사람이 손으로 실행

## 참고한 페이지의 구조

공개 페이지라 블록 트리를 그대로 받아 볼 수 있었다(`notion.site/api/v3/loadCachedPageChunkV2`).
노션 데이터베이스는 하나도 안 쓴다 — 전부 일반 블록 + 단순 표다.

```
N사 플레이스 · Marketing Agency I 티에스애드
├ ‣ 문의 채널              버튼(카톡)
├ 🌠 프로그램 접수 양식     통합양식 .xlsx / 토글 3개 / 작성법 .zip
├ 🔎 플레이스 안내         앵커 링크 3개 + 카테고리 버튼 9개
├ 📌 접수 가능 프로그램     표 9열 × 12행
├ ✅ 플레이스 래퍼런스      이미지
└ ‣ 접수 프로그램 안내
```

우리 페이지는 같은 뼈대에 내용만 바꿨다 — 시작하기 3단계 / 충전 요청 ①~⑥ / 주문서 작성 /
접수 조건 / 자주 묻는 질문 / 바로가기.

## ERP 가이드와의 관계

ERP 안에는 이미 단계별 투어가 있다(`ChargeGuide` · `CustomerGuide`, 빨간 네모로 짚어 주는 방식).
그건 **로그인 후** 열린다. 노션 페이지는 **로그인 전** 사람을 위한 것이다 — 상담 중인 업체,
계정을 아직 못 받은 담당자, 카톡으로 "어떻게 하는 거냐" 묻는 사람.

같은 내용이 두 곳에 있으면 어긋난다. 그래서 경계를 이렇게 긋는다.

| | 노션 | ERP 가이드 |
|---|:--:|:--:|
| 전체 흐름 (충전 → 접수 → 발행) | ● | ● |
| **무엇을 준비해 오셔야 하는지** (네이버 계정·사진·키워드·2단계 인증) | ● | ● |
| 어느 버튼이 화면 어디에 있는지 | **✕** | ● |
| 실시간 잔여 건수 · 진행 상태 · 입금 계좌 | ✕ | ● |
| **금액** | **✕ 절대** | ● |
| **접수 폼 / 엑셀 양식** | **✕ 절대** | ● |

노션에는 **화면 세부를 쓰지 않는다.** 버튼 위치·칸 이름을 적으면 화면이 바뀌는 순간
노션이 먼저 거짓말을 시작한다. "무엇을 준비해 오셔야 하는지"까지만 쓰고, 조작은 ERP 투어에 맡긴다.

## 절대 넘어가면 안 되는 두 가지

### ① 엑셀 접수 양식

참고 페이지의 핵심이 이것인데, **그대로 베끼면 사고가 기본값이 된다.**
접수가 `cafe_deploy_requests` 로 들어와야 여섯 배선이 자동으로 걸린다
([카페-계약-자동화-구조.md](카페-계약-자동화-구조.md)). 엑셀·카톡 접수는 그 여섯을 전부 우회한다 —
게시판 크롤에 안 잡혀 **글이 영영 추적되지 않고**, 선불 잔액 검증도 지나쳐 잔액 0인데 발행을 약속하게 된다.

경보 신호: 카톡·메일·엑셀 접수가 **월 1건이라도** 생긴다 / 담당자가 접수를 손으로 ERP에 옮겨 적는다.

### ② 금액

공개 단가 + 대행사가 부른 값 = 하부가 마크업을 즉시 역산한다. **대행사가 하부를 직거래로
뺏길까 봐 우리를 떠난다** — 3계층 구조 자체가 무너진다. 직거래 고객에게 금액을 안 띄우는
규칙(2026-08-10)과도 정면으로 충돌한다. 노션 공개 페이지는 검색엔진·공개 API로 캐시되어 지워도 남는다.

`notion_publish.py` 가 발행 직전에 본문을 검사해 금액 표현이 하나라도 있으면 발행을 거부한다.
검사는 일부러 느슨하다 — 오탐은 30초면 확인하고, 놓치면 되돌릴 수 없다.
(실제로 초안의 `단가` 두 줄이 걸려 문구를 바꿨다. 검사를 푸는 대신 문구를 바꾸는 쪽이 맞다.)

경보 신호: 초안에 "원" 글자가 등장 / 회의에서 "예시 단가" 라는 말이 나옴 /
**하부업체가 갑자기 단가를 물어본다**(이미 샜다는 뜻).

## ERP → 노션 자동 동기화는 만들지 않는다

대상이 공집합이다.

| 후보 | ERP에 원천 | 공개 가능 | 판정 |
|---|:--:|:--:|---|
| 토큰 단가 | ○ `app_settings.token_unit_price` | **✕ 절대** | 파이프를 깔면 안 됨 |
| 대행사→하부 단가 | ○ `agency_token_transfers.unit_price` | ✕ 절대 | 〃 |
| 안내 문구·절차 | △ 가이드 코드 문자열 | ○ | 문구는 사람이 다듬는다 |
| 마감시간·최소수량·주말접수·환불 | **✕ 없음** | ○ | 원천부터 만들어야 함 |

자동화할 수 있는 값은 전부 공개 금지이고, 공개해도 되는 값은 원천이 없거나 사람 손이 낫다.
파이프를 깔아 두면 하는 일 없이 "언젠가 단가가 새어 나갈 통로"만 남는다.

## 남은 빈칸

`카페배포-고객안내.md` 의 「접수 조건」 두 번째 표가 비어 있다 — **당일 접수 마감 / 최소 접수 건수 /
주말 접수 / 환불 규칙**. 담당자가 카톡으로 반복해서 답하는 내용이다.
빈 채로 발행하지 말 것. 빈 표는 없느니만 못하다.

## 노션 API — 실측으로 확인한 경계

| | |
|---|---|
| 인증 | 내부 연동 토큰(`ntn_`) 하나. OAuth 불필요 |
| API 버전 | `2026-03-11` — Views API·마크다운 API가 이 버전부터 |
| 만들 수 있는 블록 | callout · toggle · table · column · divider · image · file · code · quote · 목차 |
| 재실행 | `PATCH /v1/pages/{id}/markdown` `replace_content` 로 본문 전체 교체 |
| 파일 첨부 | `.xlsx` `.zip` 가능하지만 **우리는 쓰지 않는다**(위 ①) |
| 한도 | 연동당 평균 초당 3회, 429 시 `Retry-After` 준수. 요청당 자식 100개 · 중첩 2단 |
| 요금 | API는 무료 플랜 포함. **커스텀 도메인은 유료 플랜 + 월 8~10달러 별도** |

**API로 안 되는 것:**

1. **웹 게시 토글** — 켜는 엔드포인트가 없다. 최초 1회 노션 화면에서 사람이 켠다
2. **버튼 블록 생성** — 참고 페이지의 버튼 11개가 그것이다. 링크 텍스트로 대체했다
3. **synced block 내용 갱신** — 공통 블록을 여러 페이지에 뿌리고 한 번에 고치는 설계는 못 쓴다

## 발행 절차

```
1. app.notion.com/developers/connections → 내부 연동 생성 → 토큰(ntn_...) 복사
2. 부모로 쓸 노션 페이지 생성 → ••• → Connections → 그 연동 추가
3. .env 에  NOTION_TOKEN=...  NOTION_PARENT_PAGE_ID=...
4. python crawler/notion_publish.py --check     금액 검사만
   python crawler/notion_publish.py --dry-run   보낼 내용 확인
   python crawler/notion_publish.py             발행
5. 노션 화면에서 '웹에 게시' 1회 토글 → 나온 page id 를 .env 의 NOTION_PAGE_ID 에
   (이후 실행은 새로 만들지 않고 본문만 교체한다)
```

내용을 고칠 때는 **노션이 아니라 `카페배포-고객안내.md` 를 고친다.**
노션에서 직접 고치면 다음 발행 때 통째로 덮여 사라진다.
