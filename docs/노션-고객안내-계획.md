# 공개 고객 안내 페이지 — 노션 검토 결과와 계획

2026-08-21. 티에스애드의 공개 노션 페이지(`N사 플레이스`)를 참고해 우리도 만들지 검토했다.
독립검증 두 축(노션 API 실측 · 설계 검토)을 돌린 결과를 남긴다.

## 참고한 페이지의 실제 구조

공개 페이지라 블록 트리를 그대로 받아 볼 수 있었다(`notion.site/api/v3/loadCachedPageChunkV2`).
노션 데이터베이스는 하나도 안 쓴다 — 전부 일반 블록 + 단순 표다.

```
N사 플레이스 · Marketing Agency I 티에스애드
├ ‣ 문의 채널              버튼(카톡)
├ 🌠 프로그램 접수 양식     통합양식 .xlsx / 토글 3개 / 작성법 .zip
├ 🔎 플레이스 안내         앵커 링크 3개 + 카테고리 버튼 9개
├ 📌 접수 가능 프로그램     표 9열 × 12행
├ ✅ 플레이스 래퍼런스      이미지
└ ‣ 접수 프로그램 안내
```

표 열: `종류(추천) · 당일구동 · 최소일수 · 최소수량 · 환불 · 주말접수 · 작업키워드 · 프로그램 · 마감시간`

## 판단

**빈 구멍은 진짜로 있다.** 계정 없는 사람(상담 중인 업체, 신규 대행사)에게 "무엇을 어떤 조건으로
접수할 수 있는지" 보여줄 곳이 우리에게 없다. ERP의 가이드 두 개는 전부 로그인·승인 이후에만 열린다.

**그런데 그 값을 주는 것은 노션이 아니라 '프로그램 스펙 시트'라는 내용물이다.**
우리는 이미 로그인 없는 공개 페이지 인프라를 갖고 있다(`functions/r/[id].ts` — Supabase에 HTML 저장 →
`/r/:id` 서빙 → `/og/:id.png` 카톡 썸네일). 노션이 추가로 주는 것은 "비개발자가 배포 없이 고친다"
하나인데, 이 저장소는 Pages 자동배포라 그 이점도 얇다.

> **노션은 4주짜리 임시 검증 도구로만 쓴다. 값이 확인되면 ERP로 흡수하고 노션은 버린다.**

## ERP → 노션 자동 동기화는 만들지 않는다

대상이 공집합이다.

| 후보 | ERP에 원천 | 공개 가능 | 판정 |
|---|:--:|:--:|---|
| 토큰 단가 | ○ `app_settings.token_unit_price` | **✕ 절대** | 파이프를 깔면 안 됨 |
| 대행사→하부 단가 | ○ `agency_token_transfers.unit_price` | ✕ 절대 | 〃 |
| 상품·세부유형 목록 | △ `src/lib/products.ts` 상수 | ○ | 연 몇 회 → 손으로 |
| 마감시간·최소수량·당일구동·환불 | **✕ 없음** | ○ | 원천부터 만들어야 함 |
| 인사말·레퍼런스·이미지 | ✕ | ○ | 사람이 쓰는 것 |

자동화할 수 있는 값은 전부 공개 금지이고, 공개해도 되는 값은 전부 원천이 없다.
파이프를 깔아 두면 하는 일 없이 "언젠가 단가가 새어 나갈 통로"만 남는다.

그래서 원천은 [docs/notion/프로그램-스펙.md](notion/프로그램-스펙.md) **한 파일**이고,
사람이 고친 뒤 [crawler/notion_publish.py](../crawler/notion_publish.py) 를 손으로 돌린다.

## 노션에 둘 것 / ERP에 둘 것

원칙: **노션 = 무엇을 파는가(변하지 않는 상품 규칙) / ERP = 어떻게 넣고 얼마인가(사람·돈·상태).**

| | 노션 | ERP |
|---|:--:|:--:|
| 상품 종류·프로그램명 | ● | 참조 |
| 최소수량·최소일수·당일구동·주말접수·마감시간 | ● | ✕ |
| 환불·차감 규칙(문장) | ● | ✕ |
| 레퍼런스 이미지·인사말·문의 채널 | ● | ✕ |
| **단가·금액** | **✕ 절대** | ● |
| **접수 폼·주문서** | **✕ 절대** | ● |
| 잔여 건수·충전·입금 계좌 | ✕ | ● |
| 화면 조작법 | ✕ | ● (GuideOverlay) |
| 접수 진행 상태·순위·보고서 | ✕ | ● |

두 곳에 같은 내용이 있으면 반드시 어긋난다. 막는 방법은 **쓰지 않는 것**뿐이다.
노션에는 접수 방법을 한 줄도 쓰지 않고, 링크 하나만 둔다 — 「고객 ERP에서 접수하기 →」.

## 절대 넘어가면 안 되는 두 가지

### ① 엑셀 접수 양식

참고 페이지의 핵심이 이것인데, **그대로 베끼면 사고가 기본값이 된다.**
접수가 `cafe_deploy_requests` 로 들어와야 여섯 배선이 자동으로 걸린다
([카페-계약-자동화-구조.md](카페-계약-자동화-구조.md)). 엑셀·카톡 접수는 그 여섯을 전부 우회한다 —
게시판 크롤에 안 잡혀 **글이 영영 추적되지 않고**, 선불 잔액 검증도 지나쳐 잔액 0인데 발행을 약속하게 된다.

경보 신호: 카톡·메일·엑셀 접수가 **월 1건이라도** 생긴다 / 담당자가 접수를 손으로 ERP에 옮겨 적는다.

### ② 금액

공개 15,000 + 대행사가 부른 값 = 하부가 마크업을 즉시 역산한다. **대행사가 하부를 직거래로
뺏길까 봐 우리를 떠난다** — 3계층 구조 자체가 무너진다. 직거래 고객에게 금액을 안 띄우는
규칙(2026-08-10)과도 정면으로 충돌한다. 노션 공개 페이지는 검색엔진·공개 API로 캐시되어 지워도 남는다.

`notion_publish.py` 가 발행 직전에 본문을 검사해 금액 표현이 하나라도 있으면 발행을 거부한다.
검사는 일부러 느슨하다 — 오탐은 30초면 확인하고, 놓치면 되돌릴 수 없다.

경보 신호: 초안에 "원" 글자가 등장 / 회의에서 "예시 단가" 라는 말이 나옴 /
**하부업체가 갑자기 단가를 물어본다**(이미 샜다는 뜻) / ERP→노션 동기화 얘기가 다시 나온다.

## 단계

| 단계 | 하는 일 | 끝났다는 판정 |
|---|---|---|
| 1. 스펙 채우기 (개발 0) | 담당자가 카톡으로 반복해 답하는 내용을 `docs/notion/프로그램-스펙.md` 빈칸에 채운다 | 그 표만 보고 최근 문의 10건 중 **8건 이상**을 추가 확인 없이 답할 수 있다. 못 채우면 **여기서 중단** — 만들 내용이 아직 없다는 뜻 |
| 2. 발행 | 토큰·부모 페이지 준비 → `notion_publish.py` → 노션에서 '웹에 게시' 1회 토글 | 금액 검사 0건 · ERP 링크가 `/login` 으로 정확히 감 · 신규 문의 1건을 링크만 보내 접수까지 완주 |
| 3. 값 측정 (2~4주) | 신규 문의에 무조건 이 링크부터 보낸다. 링크 후 가입·접수 전환과, 링크 외에 추가로 설명한 항목을 기록 | 4주 뒤 — 담당자 설명 시간이 줄었으면 4단계, **안 줄었으면 노션을 지우고 종료.** 이 종료는 실패가 아니라 정상 결과다 |
| 4. ERP 흡수 | `program_specs` 테이블 + `/guide` 공개 라우트를 `functions/r/[id].ts` 패턴으로. 노션 표는 지우고 링크만 남김 | 노션에 표가 0개다(단일 출처 달성) |

3단계에서 끝나는 것이 가장 흔하고 가장 값싼 결말이다. 그걸 미리 허용해 두는 것이 이 계획의 핵심이다.

## 노션 API — 실측으로 확인한 경계

| | |
|---|---|
| 인증 | 내부 연동 토큰(`ntn_`) 하나. OAuth 불필요(남의 워크스페이스에 설치될 때만 필요) |
| API 버전 | `2026-03-11` — Views API·마크다운 API가 이 버전부터 |
| 만들 수 있는 블록 | callout · toggle · table · column · divider · image · file · code · quote · 목차 |
| 데이터베이스 뷰 | `POST /v1/views` 로 table/board/list/calendar/timeline/gallery/**form**/chart/map/dashboard |
| 파일 첨부 | `.xlsx` `.zip` 가능. **무료 5MiB/개**, 유료 5GiB. 업로드 후 1시간 내 첨부 안 하면 자동 폐기 |
| 재실행 | `PATCH /v1/pages/{id}/markdown` `replace_content` 로 본문 전체 교체 |
| 한도 | 연동당 **평균 초당 3회**, 429 시 `Retry-After` 준수. 요청당 자식 100개 · 중첩 2단 · rich_text 2,000자 |
| 요금 | API는 무료 플랜 포함. **커스텀 도메인은 유료 플랜 + 월 8~10달러 별도** |

**API로 안 되는 것** — 설계에 영향을 준 것만:

1. **웹 게시 토글** — 켜는 엔드포인트가 없다. 최초 1회 노션 화면에서 사람이 켠다. `public_url` 은 게시 후 조회만
2. **버튼 블록 생성** — 참고 페이지의 버튼 11개가 그것이다. 읽으면 `unsupported`. 링크 텍스트나 폼 뷰로 대체
3. **synced block 내용 갱신** — 공통 블록을 여러 페이지에 뿌리고 한 번에 고치는 설계는 못 쓴다

## 사람이 해야 할 준비

1. `app.notion.com/developers/connections` → 내부 연동 생성 → 토큰 복사
2. 부모로 쓸 노션 페이지 생성 → `•••` → Connections → 그 연동 추가
3. `.env` 에 `NOTION_TOKEN`, `NOTION_PARENT_PAGE_ID`
4. 발행 후 노션 화면에서 '웹에 게시' 1회 토글 → 나온 페이지 id 를 `.env` 의 `NOTION_PAGE_ID` 에
